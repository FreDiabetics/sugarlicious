# Hilt integration implementation plan

Goal: lifecycle-safe Hilt dependency injection in Mobile, Sugarlicious Wear and SugarWear, preserving behavior.
Architecture: @HiltAndroidApp roots, @AndroidEntryPoint Android hosts, @HiltViewModel creation. Existing constructor test seams remain; application-context repositories supplied by per-feature modules. Runtime editor arguments use assisted injection; lifecycle scopes remain owned/cancelled exactly as before. Collector resources remain lazy until after foreground promotion.
Spec: latest user request and existing architecture plan; no commits, PR, push, installation, protocol or BLE timing edits.
Tech: Hilt 2.60.1, KSP 2.3.13 (official current docs), existing AGP9.4.1/Kotlin2.4.10.

## Steps
- [ ] Add failing graph/lifecycle smoke tests for all three application roots.

- [ ] Full tests/build/lint/ktlint/Detekt/architecture and Kover in both roots sequentially; final independent review, source/hash guard, no Git operations.

## Risks and checks
- Application roots must still run migration setup unchanged.
- ViewModels must be retained across recreation and different keys remain isolated.
- Runtime editor values/target/widget identity must not leak between instances.
- Source-settings scope cancellation must survive retained lifecycle.
- Collector must not create storage, BLE or alarms before existing start points.
- Existing Robolectric tests run with real application graph; generated Hilt code is not hand-written or suppressed.
